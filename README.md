# Turing 3.5 Neon Monitor

Панель мониторинга для USB-дисплея Turing Smart Screen 3.5″ (480 × 320) на Windows. Показывает состояние ПК и лимиты OpenCode, Claude и Codex на неоновой теме.

## Возможности

- Часы и дата; CPU, GPU и RAM; заполнение дисков `C:` и `Z:`.
- Неоновая тема и частичное обновление изменившихся областей экрана. Движущиеся блики по умолчанию отключены для снижения нагрузки на USB-соединение.
- OpenCode: `Д` — rolling/five-hour, `Н` — неделя, `М` — месяц. Шкала показывает месячное использование.
- Claude: оранжевые `К5` и `КН` — использованные проценты за пять часов и неделю.
- Codex: белые `G5` и `GН` — использованные проценты за пять часов и неделю.
- Шкалы под Claude и Codex показывают пятичасовое использование. `--` означает, что данные источника недоступны.
- Значок в системном трее и автозапуск при входе в Windows.

Показатели сервисов запрашиваются при запуске и затем каждые пять минут. Баланс OpenCode не запрашивается.

## Требования

- Windows 10/11 x64 и совместимый USB-дисплей 480 × 320.
- Go 1.23 или новее — только для сборки из исходников.
- Для данных NVIDIA используется `nvidia-smi`; доступность температуры и мощности CPU зависит от датчиков Windows или LibreHardwareMonitor.
- Подписи дисков `C:` и `Z:` заданы в `stable.go`. Если диска `Z:` нет, его показатели будут недоступны; для другого диска измените код и подпись темы.

## Запуск

Готовая версия для Windows: [скачать Turing35NeonStableV47.exe](https://github.com/Altersam/3.5inch-turing-smart-screen/raw/refs/heads/main/Turing35NeonStableV47.exe).

1. Подключите экран и закройте другие программы, использующие его COM-порт.
2. Запустите `Turing35NeonStableV47.exe` или соберите его по инструкции ниже.
3. Значок программы появится в системном трее. Обычный запуск добавляет программу в автозапуск текущего пользователя Windows.

Приложение ищет устройство `VID_1A86&PID_5722`; если оно не найдено, используется `COM5`. Порт можно указать вручную перед запуском:

```powershell
$env:TURING_COM = 'COM5'
.\Turing35NeonStableV47.exe
```

Для просмотра макета без подключения дисплея:

```powershell
.\Turing35NeonStableV47.exe --preview
```

Файл `neon_preview.png` появится рядом с EXE. При обычном запуске журнал `app_neon.log` также создаётся рядом с EXE. В начале каждого часа журнал обнуляется на месте; сохраняются записи текущего часа. При запуске старый журнал предыдущего часа тоже очищается.

Обычный запуск и автозагрузка обновляют часы и показатели без движущихся бликов. Эта конфигурация прошла более двух часов непрерывной передачи обновлений без ошибок COM после переподключения экрана. В предыдущей проверке без бликов также наблюдался тайм-аут, поэтому отключение анимации снижает нагрузку, но не доказывает устранение первопричины USB-сбоев. Для отдельного диагностического запуска анимацию можно включить аргументом `--no-glow=false`.

## Сборка и проверка

Откройте PowerShell в папке проекта:

```powershell
go test -v ./...
go vet ./...
.\build.ps1
```

Либо выполните сборку вручную:

```powershell
go build -ldflags '-H=windowsgui -s -w' -o Turing35NeonStableV47.exe .
```

Тесты и сборка рассчитаны на Windows. В репозитории опубликован готовый `Turing35NeonStableV47.exe`; остальные локальные EXE и журналы исключены через `.gitignore`. GitHub Actions также выполняет тесты, проверку `go vet` и сборку EXE, доступного в артефактах запуска workflow.

## Подключение лимитов

### OpenCode

Используется ключ провайдера `opencode-go` из `~/.local/share/opencode/auth.json` или `%APPDATA%\opencode\auth.json`. Можно также задать переменную `OPENCODE_API_KEY`. Если rolling-данные недоступны, блок OpenCode не выводится; при отсутствии в ответе недельного или месячного поля текущая версия подставляет `0`.

### Claude

Установите [Claude Code](https://code.claude.com/) и войдите в подписку Claude:

```powershell
claude auth login --claudeai
```

Программа читает действующий локальный токен Claude Code и не обновляет его самостоятельно. Если вход истёк, показатели будут `--`; повторите вход. Источник статистики Claude использует недокументированный endpoint, который может измениться.

### Codex

Установите [Codex](https://developers.openai.com/codex/) и войдите с ChatGPT. Приложение использует локальный `codex app-server` и его метод `account/rateLimits/read`. Проверяются окна именно на 300 и 10080 минут; отсутствующее окно отображается как `--`.

## Если экран остановился

Проверьте `app_neon.log` рядом с программой. При ошибках COM убедитесь, что экран не занят другим приложением; если Windows сообщает, что устройство не функционирует, переподключите его по USB. Программа периодически повторяет подключение. После двух последовательных сбоев она также пробует перезапустить именно USB-устройство дисплея через `pnputil` (не чаще раза в пять минут); для этого действия нужны уже имеющиеся права администратора. Неудача записывается в журнал, обычные попытки подключения продолжаются.

Начиная с V45, изображение передаётся блоками до 3840 байт со скоростью до 48 КиБ/с и паузой 40 мс между областями. Тайм-аут отдельной записи — 3 секунды. При открытии порта очищаются старые очереди и читается ответ HELLO. Запись `COM opened` означает только открытие порта; успешная передача изображения отмечается `COM frame done`. Начиная с V46, используется `no_glow=true` по умолчанию, включая автозагрузку.

Если `--` отображается у Claude или Codex, проверьте вход в соответствующий клиент и подождите следующий опрос.

## Структура

```text
stable.go          дисплей, датчики, рендер и системный трей
serial_transport.go ограничение размера и скорости USB-записей
serial_recovery.go  адресное восстановление USB-устройства дисплея
hourly_log.go      ежечасное обнуление журнала
usage_limits.go    получение лимитов Claude и Codex
stable_test.go     тесты рендера, протокола и лимитов
serial_transport_test.go тесты USB-передачи и выбора устройства
hourly_log_test.go тесты очистки журнала на границе часа
assets/            встроенный фон, иконка и растровые шрифты
build.ps1          сборка EXE для Windows
.github/workflows/ тест и сборка в GitHub Actions
```

`gen_fonts.py` и `prepare_base.py` — вспомогательные скрипты для работы с графикой; они не нужны для обычной сборки.
